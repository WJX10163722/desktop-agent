---

## 什么时候用
用户想验证代码是否正常，或报告了某个功能坏了需要定位。

## 步骤
1. 先跑最快的一组：`python tests/test_tools.py`，不要一上来五组全跑。
2. 如果第一组绿了再跑其余：`python tests/test_server.py`、`python tests/test_mcp.py`、`python tests/test_agent.py`、`python tests/test_session.py`。
3. 只关注**失败的行**（FAIL 开头），每组最多细读 3 条失败。
4. 每条失败总结成四行：哪个用例 / 期望什么 / 实际什么 / 最可能的原因。

## 不要做什么
- 不要顺手改代码——这一步只报告，改不改由用户决定。
- 不要把整段 traceback 原样贴给用户，只提炼上面四行。
- 不要为了"全绿"去改测试断言来迁就实现。

## 怎么算做完了
- 五组测试都跑过，或至少跑过与问题相关的一组。
- 每条失败都有"期望 / 实际 / 可能原因"三要素。
- 如果全绿，明确说"X 组共 Y 条全部通过"，不要编造失败。
